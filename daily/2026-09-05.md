Problem 1：209. Minimum Size Subarray Sum

原始来源： LeetCode

链接： [209. Minimum Size Subarray Sum](https://leetcode.com/problems/minimum-size-subarray-sum/?utm_source=chatgpt.com)

难度： Medium

考点： 滑动窗口、双指针、正数数组的单调性


题目描述

给定一个正整数数组 nums 和正整数 target，找出满足“子数组元素和大于等于 target”的最短连续子数组长度；如果不存在，返回 0。

例如：

target = 7
nums = [2,3,1,2,4,3]

答案是 2，因为 [4,3] 的和为 7。

核心思路

因为数组中的每个数都是正数，所以窗口具有单调性：

右指针向右移动，窗口和只会增加；

当窗口和已经达到 target 后，可以不断右移左指针，尝试缩短窗口；

每个元素最多进窗口一次、出窗口一次，因此总复杂度是线性的。


维护：

left：窗口左端点

right：窗口右端点

sum：当前窗口元素和

ans：当前最短长度


遍历 right：

1. 把 nums[right] 加入窗口；


2. 如果 sum >= target，更新答案；


3. 不断移动 left，直到窗口和重新小于 target。



C++ 标准解法

#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int n = nums.size();
        int ans = n + 1;
        long long sum = 0;
        int left = 0;

        for (int right = 0; right < n; ++right) {
            sum += nums[right];

            while (sum >= target) {
                ans = min(ans, right - left + 1);
                sum -= nums[left++];
            }
        }

        return ans == n + 1 ? 0 : ans;
    }
};

复杂度分析

时间复杂度：O(n)

空间复杂度：O(1)


易错点

1. 这套滑动窗口写法依赖“数组元素全部为正数”。


2. 条件是 sum >= target，不是 sum > target。


3. 收缩窗口时，要先更新答案，再移出左端元素。


4. 题目要的是连续子数组，不是任意子序列。


5. 复杂度虽然有嵌套 while，但两个指针总共最多移动 2n 次，仍然是 O(n)。



可迁移总结

看到下面这种结构时，优先考虑滑动窗口：

正数数组
+ 连续区间
+ 和达到某个阈值
+ 求最短或最长

常见套路就是：

右扩展，直到满足条件；
左收缩，优化答案。

Problem 2：416. Partition Equal Subset Sum

原始来源： LeetCode

链接： [416. Partition Equal Subset Sum](https://leetcode.com/problems/partition-equal-subset-sum/?utm_source=chatgpt.com)

难度： Medium（偏上）

考点： 0/1 背包、状态压缩、动态规划建模


题目描述

给定一个只包含正整数的数组 nums，判断能否把它分成两个子集，使两个子集的元素和相等。

例如：

nums = [1,5,11,5]

可以分成：

[1,5,5] 和 [11]

因此返回 true。

核心思路

设数组总和为 total。

如果 total 是奇数，不可能平分；

如果 total 是偶数，只需要判断能否选出一些元素，使它们的和等于 total / 2。


于是问题转化为：

> 从数组中每个元素最多选一次，能否恰好凑出目标值 target？



这就是经典的 0/1 背包判定问题。

定义：

dp[j] = 是否可以用已经处理过的元素，凑出和 j

初始状态：

dp[0] = true

因为不选任何元素时，和为 0。

加入一个数 x 时：

dp[j] = dp[j] || dp[j - x]

但 j 必须从大到小遍历。原因是：

从大到小：当前元素只会被使用一次，符合 0/1 背包；

从小到大：同一个元素可能在同一轮中被重复使用，会错误地变成完全背包。


C++ 标准解法

#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int total = accumulate(nums.begin(), nums.end(), 0);

        if (total % 2 == 1) {
            return false;
        }

        int target = total / 2;
        vector<bool> dp(target + 1, false);
        dp[0] = true;

        for (int x : nums) {
            for (int j = target; j >= x; --j) {
                dp[j] = dp[j] || dp[j - x];
            }
        }

        return dp[target];
    }
};

复杂度分析

时间复杂度：O(n * target)

空间复杂度：O(target)


其中：

target = total / 2

易错点

1. 总和为奇数时，必须直接返回 false。


2. 这是 0/1 背包，容量必须倒序枚举。


3. dp[j] 表示“是否恰好凑出 j”，不是最大价值。


4. 不需要真的构造出两个子集，只判断能否凑出一半即可。


5. 不要把“每个元素只能用一次”误写成可重复使用。



可迁移总结

看到下面这种题型，优先考虑 0/1 背包：

每个元素最多选一次
+ 是否能凑出某个目标和

而“等和划分”通常可以按这个顺序处理：

先求总和
→ 判断奇偶
→ 目标变成总和的一半
→ 转成 0/1 背包
